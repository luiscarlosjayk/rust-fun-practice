# CLAUDE.md — Rust LeetCode Practice Monorepo

Cargo workspace of independent crates, each one LeetCode-style problem solved in Rust. Goal: fluency with std types (Vec, HashMap, HashSet, String/&str, iterators) and DSA practice.

## MOST IMPORTANT RULE: `main` = stubs only (MUST)

- The `main` branch is the public, STUBS-ONLY branch. Every problem's `src/lib.rs` on `main` MUST remain an unsolved `todo!()` stub.
- NEVER commit personal solutions to `main`. On `main`, the README Progress table shows every problem as unsolved (open box).
- Personal solutions live ONLY on owner working branches (e.g. `luisk`) — never on `main`.
- Adding a problem: scaffold it as a STUB on `main` (filled-in README, real tests, warning-free `todo!()` lib.rs), commit to `main`. SOLVE it only on a personal branch.
- To pull newly-added stub problems into a personal branch, merge `main` into that branch.

## Repository Layout

- Each problem is an independent crate at `<level>/<topic>/<NNNN-slug>/`.
- Levels: `easy`, `medium`, `hard`.
- Topics: `arrays-hashing`, `binary-search`, `dynamic-programming`, `linked-list`, `math`, `sliding-window`, `stack`, `strings`, `trees`, `two-pointers`. (Not every level has every topic.)
- `NNNN` is the zero-padded 4-digit LeetCode problem number; slug is kebab-case (e.g. `0001-two-sum`).
- Per-crate files: `Cargo.toml`, `README.md` (problem statement), `src/lib.rs` (solution), `tests/tests.rs` (test cases).
- Root `Cargo.toml` is the `[workspace]` (`resolver = "2"`); its `members` array lists every crate path. The line `# NEW_PROBLEM_MARKER` is the insertion point — `new-problem.sh` adds new members above it.

### Naming rules

- Crate package name (`[package] name`) = slug with the leading `NNNN-` stripped, dashes kept (e.g. `0001-two-sum` → `two-sum`).
- Library import name = package name with dashes → underscores (e.g. `two-sum` → `two_sum`). Use it in tests as `use two_sum::...`.
- A slug (after stripping `NNNN-`) MUST NOT start with a digit — Rust crate names cannot start with a digit (so `0015-3sum` is invalid; use a word-based slug instead).

## Adding a New Problem

Use `new-problem.sh` with args in this exact order: `level topic NNNN-slug fn_name`.

```sh
./new-problem.sh easy arrays-hashing 0026-remove-duplicates remove_duplicates
```

It generates the crate dir with `src/` and `tests/`, and:
- `Cargo.toml` — package name from slug (`NNNN-` stripped), `version = "0.1.0"`, `edition = "2024"`, `[lib] path = "src/lib.rs"`.
- `src/lib.rs` — `//!` header + a parameterless `pub fn <fn_name>() { todo!("implement <fn_name>") }` stub.
- `tests/tests.rs` — `use <lib>::...;` + an `example_1` test placeholder.
- `README.md` — copied from root `TEMPLATE.md`.
- Inserts the crate path into the root `Cargo.toml` `members` above `# NEW_PROBLEM_MARKER`.

After scaffolding: fill in the README, add the proper function signature (args and return type), write real tests, keep `lib.rs` a warning-free `todo!()` stub, and commit to `main`. `fn_name` uses underscores. Solve only on a personal branch.

## Code Style & Stub Convention

- Edition `2024` in every crate.
- Every `lib.rs` starts with `//! See README.md for the problem statement.`
- An unsolved problem starts as a parameterless stub (generated by `new-problem.sh`). After you add the real function signature, apply the warning-free `todo!()` pattern: bind args with `let _ = (...)` to silence unused-variable warnings, then `todo!("implement <fn>")`.

**Example: generated stub (parameterless)**
```rust
//! See README.md for the problem statement.

pub fn search() {
    todo!("implement search")
}
```

**After you fill in the signature:**
```rust
//! See README.md for the problem statement.

pub fn search(nums: Vec<i32>, target: i32) -> i32 {
    let _ = (&nums, target);
    todo!("implement search")
}
```

- Keep the workspace warning-free at all times.
- Linked-list problems use this exact `ListNode` definition:

```rust
#[derive(PartialEq, Eq, Clone, Debug)]
pub struct ListNode {
    pub val: i32,
    pub next: Option<Box<ListNode>>,
}

impl ListNode {
    #[inline]
    pub fn new(val: i32) -> Self {
        ListNode { val, next: None }
    }
}
```

## Test Conventions

- Tests live in each crate's `tests/tests.rs`; import with `use <lib>::<fn>;` (lib = package name, dashes → underscores).
- One `#[test]` per example/edge case, with descriptive names (e.g. `example_1`, `both_empty`, `odd_total`, `disjoint_ranges`).
- Helper patterns:
  - Linked lists: `from_vec` / `to_vec` to convert between `Vec` and `Option<Box<ListNode>>`.
  - Order-independent output (e.g. group-anagrams): a `normalize`/sort helper before comparison.
  - `f64` results: epsilon compare, e.g. `(got - expected).abs() < 1e-9`.
- An UNSOLVED stub is EXPECTED to panic with "not yet implemented" — that is normal until the problem is solved (on a personal branch).

## Commands

```sh
cargo test -p <slug>      # one problem, e.g. cargo test -p two-sum
cargo test                # every problem in the workspace
cargo build --workspace   # build all crates
```
